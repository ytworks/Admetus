# Progress

Cross-session memory for Admetus: what exists, what is measured, what is not done,
and what to pick up next. Read this first, then `CLAUDE.md`.

Last updated: 2026-11-28. Branch `feat/core-featurizer-and-data`, PR #1.
204 tests pass with `-m 'not slow'`, `ruff check .` is clean, the README pair check
passes, and CI runs the whole suite on Ubuntu and macOS for Python 3.12 and 3.13.

## State

The pipeline follows the reference implementation (`models.py` and the
`Carcinogens_Lagunin` notebook) rather than extending it:

| Stage | What it does |
|---|---|
| Featurization | Morgan r=6, 2,048 bits, concatenated with the 2- and 3-point pharmacophore signature. One space for every endpoint, 89,852 columns |
| Holdout | Random 20%, seeded, via `train_test_split`, **in the order it returns**. Looked at once |
| Folds | `KFold` over the remaining 80%, no shuffle, default 3, `--folds` to raise it |
| Tuning | One Optuna `LightGBMTuner` run per fold, so the folds get different parameters |
| Ensemble | One model per fold, each early-stopped on its own validation rows. Those models ship; there is no refit |
| Output | The prediction and the spread across the fold models, which is the reference's `Confidence` |
| On top of the ensemble | Nothing. No transform, no pruning, no calibration, no threshold, no domain flag, no interval |

All 29 endpoints are trained and published as the **`models-v0.1.0`** release: 29
reproducible archives plus `models-manifest.json`, 42 MB. `models pull --all` was
verified against the published URL, installing 29 bundles that then predicted all
29 endpoints. Packaging was run twice and compared byte for byte.

Accuracy lives in the READMEs' benchmark section, generated by
`scripts/benchmark_tables.py` from the bundles. Training used `--time-budget 240`,
which is 240 seconds per fold.

## What the realignment changed, measured

- `carcinogens` held-out ROC-AUC across the realignment: **0.249 -> 0.751** when
  calibration came out (same evaluation set, so these two are comparable), then
  **0.885** once the reference's split and per-fold tuning were in place, and
  **0.901** for the bundle that ships at a 240s-per-fold budget. The reference's own
  notebook reports 0.865. `docs/benchmark.md` says which rows may be subtracted from
  which. The README quotes AUPRC for this endpoint, 0.8164, because that is its
  registered metric.
- `bioavailability` AUROC **0.5121 -> 0.6867** when the holdout stopped being sorted
  back into file order. `train_test_split` returns shuffled indices and `KFold` cuts
  contiguous blocks, so sorting them gave one fold 171 rows that were 100% positive;
  `binary_error` was minimal at iteration 1 and the model stopped there.
- Out-of-fold against held-out, on the 29 shipped bundles: out-of-fold is the more
  favourable of the two at **6** endpoints, not the 26 the earlier pipeline showed,
  and the less favourable at 23, median absolute gap 0.028. It reads pessimistic more
  often because it is one booster per row where the shipped prediction is the mean of
  all three. The figure is generated, so it cannot go stale again.

## What was removed, and why

Each of these was built here, not asked for, and measured before being removed:

- **Applicability-domain flag** (`in_domain`, `ad_score`, reference set, packed
  Tanimoto): uninformative at 16 of 29 endpoints. `dili` reported water as
  in-domain, because a flat similarity-to-error curve collapsed its threshold to
  0.0139.
- **Conformal prediction intervals**: over-covered at 8 of 9 regression endpoints,
  median 97.0% against a nominal 90%. Aspirin's Caco-2 interval was
  [-17.44, 8.18] on labels spanning -7.76 to -3.51.
- **Scaffold-grouped splitting and the feature-level leakage audit**: the reference
  splits at random. The scaffold machinery also produced a real leak -- grouping by
  input string rather than standardized structure put 9 of 129 held-out hERG
  molecules in a training scaffold -- and cost two full retrains to fix.
- **Feature-set presets, the size rule and three per-endpoint overrides**, with the
  174-run study that chose them. The reference featurizes everything identically.
- **The refit at a pooled round count**: the reference ships the fold models.
- **Probability calibration**, which was the costly one: fitted on out-of-fold
  predictions, Platt's slope came out at -37.6 on `carcinogens` and inverted the
  ranking, taking held-out AUROC from 0.7506 to 0.2494.
- **Prevalence-based column pruning**, kept one round longer than the rest on the
  argument that the tuner disables LightGBM's own rare-column guard. Removing it and
  tuning per fold took `carcinogens` from 0.751 to 0.885.

The lesson worth keeping: of 29 review findings across six rounds, **none were in the
core featurize-train-predict path**. All of them were in these added layers or in the
CLI and release machinery built to support them. The last three rounds were entirely
about reports disagreeing with exit codes, and about documents quoting numbers from a
pipeline that no longer exists.

## Decisions worth not relitigating

Measured, and still true after the simplification. `docs/benchmark.md` has the numbers.

- **Featurization is fast enough.** 3.73 ms per molecule, 848 molecules per second on
  nine workers, about two minutes per 100,000 unique molecules. An early estimate of
  28 minutes was wrong by roughly 14 times, so the vendored fast pharmacophore path
  that estimate justified was never written.
- **Mean non-zeros per molecule is 426**, not the 2,500 assumed.
- **scipy's column indexing beats a hand-rolled reindex** (11.5 ms against 20.7 ms),
  so `apply_basis` uses it.
- **`Chem.MurckoDecompose` and `rdScaffoldNetwork` are broken** in RDKit 2026.09.2,
  raising `RuntimeError: bad any cast`. No longer load-bearing, since scaffolds are
  not used, but worth knowing before anyone reaches for them.
- **Calibration cannot be made safe by measuring it.** Isotonic's ties moved average
  precision from 0.6922 to 0.6348 and Platt inverted `carcinogens` outright. The
  answer was to stop calibrating, not to pick the calibrator by measurement.
- **The automatic tuner owns the search space**, by instruction. It sets
  `feature_pre_filter` to `False`; the explicit pruning that fact justified is gone
  anyway, because removing it measured better.
- **Nothing size-dependent touches the feature space.** What still reads a row count:
  how many folds the training portion can support, and `low_confidence`.
- **A study is named after the settings its trials depend on**, including the fold
  signature, and that signature hashes dataset row identities rather than positions.
  Correcting it renamed every study, so a run interrupted before the change tunes
  from zero once and says how many trials it left behind. They are not migrated: the
  old name cannot establish which partition it measured.

## CI notes

- `admetus doctor` exits **3** when the install is sound but no model bundle is
  present, which is the normal state of a fresh checkout. The CI self-check
  accepts 0 and 3 and fails on anything else, since 1 means a broken install.
  A naive `run: admetus doctor` fails the build.
- A runner label that cannot be scheduled cancels its jobs before any step runs,
  with no log. That looks nothing like a test failure; `macos-14` did this and
  `macos-latest` fixed it.
- `concurrency: cancel-in-progress: true` cancels the previous run on every
  push, so a run marked cancelled after a quick follow-up push is expected.
- Remediation strings must name commands that exist. `doctor` and the bundle
  loader used to suggest `admetus models pull`, which is not implemented;
  pointing an automated caller at a missing command is worse than saying nothing.

## Things the code refuses to do, on purpose

Changing any of these is a behaviour change, not a cleanup.

- A molecule that fails to parse is never replaced by another one. It gets empty
  prediction cells and a reason.
- A dataset whose digest does not match the registry is refused, and a cached file
  that fails is moved aside so nothing reads it.
- A model bundle whose column space or golden fingerprint disagrees with the
  install is refused rather than used.
- Cross-validation scores are recorded as biased and are never reported as
  performance.
- Folds too thin to score are refused loudly rather than tuned against noise.
- A manifest's endpoint key must be one the registry publishes and must not name a
  directory the project keeps for itself.
- A booster that cannot be loaded, or whose width disagrees with the bundle's basis,
  stops an install before it replaces a working model.

## Verified on real data

- All 29 endpoints trained, packaged and published; `models pull --all` from the
  release URL installs them and `predict --all` appends 58 prediction columns.
- Every failure path of `predict` leaves the report agreeing with the exit status:
  success, missing input, empty model directory, `--strict` with one bad molecule,
  an unwritable output file, and an unwritable report alongside it.
- All 29 datasets fetch, normalize to the row counts pinned in the registry, and
  verify against their digests.
- The published split archive fetches, verifies and unpacks all 22 official endpoints.
- `models package` then `models pull` round-trips a bundle through a manifest, and
  packaging the same bundle twice gives byte-identical archives.
- The CSV round trip is byte-identical through a file carrying a byte-order mark,
  duplicate column names, CRLF, an embedded newline inside a quoted field, escaped
  quotes, cp932 text and no trailing newline.

## What to pick up next

- **Official protocol, 22 endpoints x 5 seeds**, at a 60-second-per-fold budget, run in
  three parallel shards. The report feeds `scripts/benchmark_tables.py --official`,
  which fills the second table in both READMEs. The budget differs from the 240
  seconds the shipped bundles were trained at, and the table has to say so.
- **A second release at a larger budget** is the obvious next measurement: 240 seconds
  per fold is what the published parameters reached, not a ceiling, and nothing has
  measured whether more buys anything.
- The `admetus_version` in the manifest reads `0.1.0.dev0`. It is the package version,
  not the model release tag, but it should stop saying `dev` before a wider release.
